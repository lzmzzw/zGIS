# 前端性能与恢复可靠性

图层、要素数组、要素及其属性遵守不可变更新：修改时创建新对象，未变化部分保留引用。恢复备份、属性搜索和撤销比较使用这个已有约定复用结果，不以图层名称或要素 ID 代替版本。

## 本轮优化

- MCP 工作区同步首次发送全量，此后只发送 features 引用或名称改变的图层及删除 ID；单独切换活动层发送空增量。串行队列跳过已过期的待发送状态，只有 IPC 成功才更新基线；失败保留旧基线并以 1–30 秒退避重试。Effect 清理取消对应重试，正在执行的成功请求仍记录其实际写入版本，供下一请求正确计算差异。
- 恢复文件沿用 version 3、30 步历史与 500000 个历史要素预算。每个图层和要素数组的安全 JSON 片段以 WeakMap 缓存，编辑草稿与选中状态变化不再重新编码大图层；历史帧的验证结果也按数组引用复用。数据库身份仍不进入恢复文件。
- 原生备份只有一个写入在执行；尚未发出的普通自动备份合并为最新版本。保存、退出与发布确认的显式备份作为顺序屏障，不能被自动备份合并或跳过。同步 localStorage 日志仍保留，覆盖原生写入尚未完成时的强退窗口。
- MCP 发布采用 `gis_results_drain` 领取、恢复备份成功、`gis_results_ack` 确认的顺序。图层 ID 使用 `mcp-publication-<publicationId>`，恢复时保留该 ID；重复领取不会添加第二份图层。编辑期间延后导入，前端待处理列表也按发布 ID 去重。退出前主动领取一次，显式备份失败则阻止正常退出。此机制覆盖 WebView 重载和确认失败，不承诺 Rust 进程重启后保留尚未持久化的发布队列。
- 浏览器选文件入口使用 Uint8Array，避免先构造 number[]。读取前检查单文件及单批总量均为 100 MB，按文件顺序读取；Worker 继续使用独立可转移缓冲区，保留原文件供预览与重试。桌面旧 IPC 的 number[] 仍兼容。
- 属性搜索按属性对象引用缓存小写字段文本，输入防抖 120 ms；不同字段分别匹配，避免跨字段拼接产生误命中。地图对同一要素数组且 OpenLayers revision 未变化的同步直接跳过；几何手势期间不建立已同步标记。
- 撤销和 dirty 比较先比较共享要素引用，只有替换的要素才比较 JSON；保留 XYZ、字段与原有 dirty 语义，不改变 30 帧撤销模型。
- 工具箱分析传入独立 jobId，取消调用 `gis_cancel_analysis`。按钮保持等待状态直到分析 Promise 真正完成；普通保存不再显示无效的“取消解析”。取消按钮位置避开底图控件。

## 验证与基准

运行 `pnpm test`、`pnpm build`；浏览器专项为 `tests/mcp.spec.ts`、`tests/processing-toolbox.spec.ts`、`tests/workspace.spec.ts`、`tests/attribute-table.spec.ts`。包括备份失败后重试、显式退出屏障、发布不重复、取消 jobId、XYZ 与编辑恢复。

运行 `node scripts/frontend-performance.mjs`，结果写入 `output/performance-20261011/frontend.json`。基准在相同的 10000 个合成 XYZ 点上复现优化前的全量图层编码和属性搜索，与优化后的热缓存执行各 20 次。2026-10-11 本机中位数：图层序列化 3.587 ms → 小于 0.001 ms；重复属性搜索 2.366 ms → 0.440 ms。这些数字仅反映未变化图层片段复用和重复搜索，不包含完整工作区字符串物化、localStorage、IPC、磁盘或地图渲染，不能作为端到端提速比例。

## 剩余边界

首次解析、首次索引、完整恢复文件拼接与写盘仍与数据量相关；单条属性替换后搜索仍需扫描要素，尚未引入 Worker 搜索。地图真实变更仍遍历要素，撤销仍保存引用数组，尚未改为完整变更集。桌面文件 IPC 仍使用现有 number[]；需要后端分块/二进制传输协议后才能消除该路径的全部复制。WeakMap 允许旧版本随文档和撤销历史释放，但不等于全进程统一内存预算。
