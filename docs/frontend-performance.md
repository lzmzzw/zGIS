# 前端性能与恢复可靠性

图层、要素数组、要素及其属性遵守不可变更新：修改时创建新对象，未变化部分保留引用。恢复备份、属性搜索和撤销比较使用这个已有约定复用结果，不以图层名称或要素 ID 代替版本。

## 本轮优化

- MCP 工作区同步首次发送全量，此后只发送 features 引用或名称改变的图层及删除 ID；单独切换活动层发送空增量。串行队列跳过已过期的待发送状态，只有 IPC 成功才更新基线；失败保留旧基线并以 1–30 秒退避重试。Effect 清理取消对应重试，正在执行的成功请求仍记录其实际写入版本，供下一请求正确计算差异。
- 同步前逐要素累计 UTF-8 字节数，并按要素数组引用缓存版本大小。超过 100 层、10 万要素或 100 MiB 时，只向原生发送拒绝原因，避免构造超限的完整 IPC；原生将旧快照标记为不可用于新分析，后续成功同步后恢复。
- 恢复文件沿用 version 3、30 步历史与 500000 个历史要素预算。快照固定修订号、白名单元数据与历史列表，按不可变要素引用重放正文；移除完整图层和整帧 JSON 字符串缓存，WeakMap 只复用历史验证结果与字节计数。历史先做长度下界与 UTF-8 预算检查，不足时省略历史，保留当前文档、编辑模式和草稿。恢复直接消费已解析对象，工作要素剥离运行期数据库身份，数据库提交基线仍按白名单独立保留。
- 原生备份只有一个写入在执行；尚未发出的普通自动备份合并为最新版本，队列保存文本源引用。自动备份在 150 ms debounce 后准备，保存、退出与发布确认的显式备份作为顺序屏障。正文按要素生成，合并为最多 256 Ki 个 UTF-16 码元的片段；保留代理对，逐片编码、等待原生确认，最多预取下一片。单片最多 1 MiB、累计 256 MiB，原生逐片写入 OS 临时文件，完整流式校验后原子替换；兼容 Tauri 字节数组降级传输。localStorage 日志最多收集 2 Mi 个 UTF-16 码元，超过即停止遍历，大快照直接走原生备份；尚在 debounce 中的自动备份没有新增日志，正常退出由显式备份屏障保证。
- 桌面 GeoJSON/CSV 保存与导出使用同一文本源：GeoJSON 逐要素投影编码，CSV 先汇总字段名，再逐行转换和转义；不创建完整导出行数组或正文字符串。原生输出暂存与恢复隔离，内存只保留当前请求及固定读写缓冲；发布时流式复制至目标同目录临时文件，sync 和长度/SHA-256 核验后原子替换。
- MCP 发布采用 `gis_results_drain` 领取、恢复备份成功、`gis_results_ack` 确认的顺序。图层 ID 使用 `mcp-publication-<publicationId>`，恢复时保留该 ID；重复领取不会添加第二份图层。编辑期间延后导入，前端待处理列表也按发布 ID 去重。退出前主动领取一次，显式备份失败则阻止正常退出。此机制覆盖 WebView 重载和确认失败，不承诺 Rust 进程重启后保留尚未持久化的发布队列。
- 浏览器选文件入口使用 Uint8Array，按文件顺序读取并复核实际字节数。桌面选择/拖入只传元数据，再按 sourceId 顺序通过原生二进制 IPC 读取；指纹采用分块 SHA-256，读取时复核大小及来源指纹。Worker 继续使用独立可转移缓冲区，保留调用方原文件供预览与重试。容量见 [大数据使用与验证](large-data.md)。
- 属性搜索按属性对象引用缓存小写字段文本（每要素超过 8192 个字符不缓存），桌面输入防抖 120 ms；2000 条以上的非空查询每片最多 512 条、以约 8 ms 为检查点让出事件循环，过期查询不发布结果；不同字段分别匹配，避免跨字段拼接产生误命中。地图对同一要素数组且 OpenLayers revision 未变化的同步直接跳过；几何手势期间不建立已同步标记。
- 撤销和 dirty 比较先比较共享要素引用，只有替换的要素才比较 JSON；保留 XYZ、字段与原有 dirty 语义，不改变 30 帧撤销模型。
- 工具箱分析传入独立 jobId，取消调用 `gis_cancel_analysis`。按钮保持等待状态直到分析 Promise 真正完成；普通保存不再显示无效的“取消解析”。取消按钮位置避开底图控件。

## 验证与基准

运行 `pnpm test`、`pnpm build`；浏览器专项为 `tests/mcp.spec.ts`、`tests/processing-toolbox.spec.ts`、`tests/workspace.spec.ts`、`tests/attribute-table.spec.ts`。包括备份失败后重试、显式退出屏障、发布不重复、取消 jobId、XYZ 与编辑恢复。

`scripts/frontend-performance.mjs` 与 `output/performance-20261011/frontend.json` 保留 2026-10-11 的历史热缓存基准；当前恢复改用逐要素生成，不再用该报告的整层字符串缓存耗时描述当前版本。大文件原生内存与耗时见 [大数据使用与验证](large-data.md)。

## 剩余边界

首次解析、恢复读取/解析、首次索引和写盘仍与数据量相关；生成单个要素 JSON 时仍可能分配大字符串。数据库提交基线的安全规范化仍可能复制完整身份数据。单条属性替换后搜索仍需分片扫描，尚未引入 Worker 搜索；搜索中的分页不回写临时空结果，完成后恢复所选行及待执行的单元格焦点。地图真实变更仍遍历要素，超过 2000 条时分片投影和维护索引；首次加载完成后显示整层，完成时重放定位与分析焦点。撤销仍保存引用数组，尚未改为完整变更集。WeakMap 不等于全进程统一内存预算。

## 大文件解析

GeoJSON 的 CRS 与要素共用一次无损解析；字符串按完整 token 交给原生 `JSON.parse` 解码，避免逐字符拼接长属性造成大量中间字符串。数字保留 `LosslessNumber`，继续保留大整数和高精度属性的原始字面量；解析深度最多 256 层，冲突重复键和无效转义明确拒绝。SHP 直接消费解析对象。新解析且尚未公开的属性/坐标原位规范化，投影只构造变换后的坐标。CSV 文本只解码一次。Worker 最多并发两个，预览 15 秒、导入 5 分钟超时后释放资源；终止、异常与取消沿用同一清理路径。

CSV 预览只传表头和前五条完整逻辑记录，最多扫描 8 MiB，保留引号及多行字段；超过采样预算时只预览完整前缀并提示。预览不证明文件后部有效，正式导入仍校验全部记录。

Worker 解析结果按图层元数据和要素批次发送；普通批次同时限制 2 MiB JSON 等价 UTF-8 数据和 1024 个要素。主线程拼接并确认后，Worker 释放对应源要素再发送下一批；失败或取消释放所有局部结果。大单要素独占一批，单要素及元数据上限均为 64 MiB，超限明确拒绝而不截断。解析完成后释放 Worker 输入缓冲；`importFiles` 内部及主线程最终图层仍是全量内存结构，这不是按文件块增量解析。

2026-11-03，本机 Node/Vite 上同一 100000 个 XYZ 点、16200041 字节 GeoJSON，旧版 `068db957b3ed219ced94799d9ce10cdfbfe9a97a` 与本次各交替测量三次：importFiles 中位数 708.04 → 290.45 ms；1700009 字节 CSV 的前五条预览仅传 94 字节。排除 Worker 传输、IPC、OpenLayers、恢复和磁盘，不作为应用端到端提速比例。复现 `node --expose-gc scripts/large-file-performance.mjs`，可追加基线 commit；报告写入独立 `output/large-file-performance-<时间戳>/`，包含本次源码 SHA-256。本轮报告为 `output/large-file-performance-1793698189534/import.json`。
